# V12.14 TEST 24 — Contact Label / Duplicate Fixes

## Source
Derived from V12.13 Test 23 corrected source.

## Findings addressed
1. Google label `Custom` appeared when B&S label was `New`. Cause: `googlePhoneType()` mapped `New` to `custom`. Fix: preserve `New` as a custom Google label string (`New`).
2. Same normalized telephone number with different labels collapsed to one Google phone entry because the sync map is keyed by normalized number. Fix: prevent duplicate normalized numbers from being saved in Edit and prevent external-number actions from adding an already-present number.
3. Deleted number reappearing in the warning remains unresolved at code level until a fresh contact reload / event sequencing trace is tested. The warning path uses the Android contact snapshot supplied to `selectContact`; a stale snapshot or asynchronous Google deletion completion remains a suspected cause.
