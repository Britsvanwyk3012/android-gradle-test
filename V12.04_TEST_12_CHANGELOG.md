# BUY & SELL V12.04 — TEST 12
## External Contact / Google Synchronisation Fix
Date: 16 September 2026

### Baseline
Derived directly from BUY_AND_SELL_V12.01_TEST_10_CAPTURE_UI_FIXES_2026-09-15.zip.
TEST 10 remains the last user-tested baseline. TEST 11 had already been issued previously, therefore this development build is uniquely numbered TEST 12 under the project numbering rule.

### Changes implemented
1. B&S → Google phone synchronisation now sends the current B&S phone list as the desired `phoneNumbers` field instead of merging old Google numbers back into the contact. This is intended to make deliberate B&S deletions propagate to Google.
2. Google custom phone labels now send the actual human label as the People API phone `type` value instead of the generic string `custom`. Standard labels continue to map to Google's predefined types.
3. New-client Google creation now sends the complete B&S phone list, including all additional numbers and their labels, instead of only the first two/WhatsApp fields.
4. Existing-client Capture → Google update now uses the complete B&S phone list when that legacy path is used.
5. When an existing client is selected, B&S compares freshly retrieved Android/Google phone numbers against the B&S SQLite phone list.
6. If an external number exists in Phone/Google Contacts but not in B&S, B&S shows `NEW NUMBER DETECTED` with controlled choices:
   - ADD TO B&S
   - ADD AS NEW NUMBER
   - REPLACE CURRENT
   - IGNORE
7. REPLACE CURRENT asks which existing B&S number should be replaced.
8. External additions/replacements are written to B&S first and then synchronised back through the existing Google sync path. No silent overwrite is performed.
9. External-number ignores are kept for the current app session to prevent the same ignored number repeatedly interrupting the same session.
10. SQLite schema version increased from 8 to 9 with an `external_phone_ignores` table reserved for future persistent ignore handling; current implementation uses an in-memory session set.
11. Visible app version updated from V12.03 to V12.04.

### Important design rules preserved
- Local B&S save completes before Google synchronisation.
- Google synchronisation failure must not lose the B&S local save.
- Existing stable Google resourceName linkage remains in use.
- No name-only automatic merging of people.
- No silent external-number import.
- Existing UNDO behaviour is untouched.
